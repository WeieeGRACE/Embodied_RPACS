# ASRPRO FPGA 串口收发与协议测试

> 2026-10-23：测距模块高阻保护管脚已同步迁移至 P6，与三路测距新版位流使用同一接线。旧 P11 版位流不可用于新接线；本次仿真、构建及 SHA256 见 `records/2026-10-23_P6_VALIDATION.md`。

| 测距保护信号 | 前方：P6 / FPGA | 左侧：P6 / FPGA | 右侧：P6 / FPGA |
| --- | --- | --- | --- |
| SCL | 7 / G16 | 13 / H13 | 17 / J13 |
| SDA | 8 / G18 | 14 / H14 | 18 / K14 |
| GPIO1 | 9 / F17 | 15 / K15 | 19 / K12 |
| XSHUT | 10 / F18 | 16 / K16 | 20 / K13 |

SCL/SDA/XSHUT 恒高阻，GPIO1 为无上下拉输入。测距模块 VIN/GND 使用专用 3.3 V 电源接线并与 FPGA 共地，不分配座子针脚。ASRPRO 串口仍为 P6-5/6。

独立工程 `asrpro_uart.gprj`，目标 ACG525 / GW5A-LV25UG324C2/I1，50 MHz。接收实际 `asrpro/asrpro.hd` 及其 README 定义的全部九种命令，回传命令响应及九种状态。**本工程模拟任务状态，所有电机输出固定低；寻找、前后 20 cm、左右 90°的实际执行不在本工程中。** 不会按延时自动播报完成，也不以语音静默作为失联。

## 接线与下载

完整分配已先写入工程根目录 `PIN_ASSIGNMENT.md`，机器可检查的同一份约束清单为 `pins.json`。

| 连接 | FPGA 管脚 | 实际位置 |
| --- | --- | --- |
| ASRPRO TX → `asr_uart_rx` | D17 / GPIO4 | **P6-5** |
| `asr_uart_tx` → ASRPRO RX | D18 / GPIO5 | **P6-6** |
| 模块 GND ↔ FPGA GND | 专用 GND | P6-12 或 P6-30 |
| 电脑串口 TX / RX（相对 FPGA） | V8 / U8 | 板载 USB 串口 |
| 复位 / 测试推进 / 故障注入 | B16 / A15 / C15 | KEY0 / KEY1 / KEY2 |
| 就绪 / 忙碌 / 错误 / 有效帧指示 | D14 / C14 / B9 / A9 | LED0 / LED1 / LED2 / LED3 |

两路 UART 都是 **115200、8N1、无流控、3.3 V TTL**。P6 与 P11 是不同连接器；P6-5/6 不等于 P11-5/6。语音模块源工程暂配置 PA2/TX、PA3/RX，但模块供电范围、UART 电平和实际插针必须按实物资料核实，不能把芯片名称直接当模块针号。模块供电不由此 FPGA 工程规定。

1. Gowin IDE 打开本目录 `asrpro_uart.gprj`，或直接使用已生成的 `impl/pnr/asrpro_uart.fs`。
2. Gowin Programmer 选择对应 GW5A 器件，下载该 `.fs` 到 **SRAM**。不要选择旧电机测试或主系统位流；本次交付没有替你下载任何设备。
3. KEY0 复位后空闲、默认中档；LED0 亮，其余灯灭。ASR 发送端保持空闲高，上电不主动向 ASR 发送任何命令或状态。
4. 七路电机引脚固定低；T11 无上下拉输入，IMU 接口保留为无上下拉输入，ToF SCL/SDA/XSHUT 为高阻。此位流不采集 IMU/ToF，不操作 OLED 或摄像头。

## 第一步：串口助手验证原始帧

先用独立 USB–TTL 适配器接 P6-5/6，共地，断开 ASRPRO，串口助手选择十六进制原始字节发送。板载 USB 串口用于调试文字，**不能把 V8/U8 与 D17/D18 共接**。

| 命令 | 发送帧（十六进制） | 测试行为 |
| --- | --- | --- |
| 寻找 | `AA 55 01 01 02 0D` | 空闲时进入 SEARCH/01 |
| 停止 | `AA 55 01 02 03 0D` | 进入 STOPPED/04；故障中保持 FAULT/06 |
| 查询 | `AA 55 01 03 04 0D` | 不改变状态 |
| 前进 | `AA 55 01 10 11 0D` | 进入模拟 MOVING/10 |
| 后退 | `AA 55 01 11 12 0D` | 同上，记录独立命令码 |
| 左旋 | `AA 55 01 12 13 0D` | 同上 |
| 右旋 | `AA 55 01 13 14 0D` | 同上 |
| 加速 | `AA 55 01 14 15 0D` | 后续动作档位上调，最多高档，不启动动作 |
| 减速 | `AA 55 01 15 16 0D` | 后续动作档位下调，最低低档，不启动动作 |

每条有效命令先收到 `AA 55 02 ACK CHECK 0D`，再收到 `AA 55 03 STATE CHECK 0D`，`CHECK=(TYPE+CODE)&FF`。ACK=00 接受、01 已运行、02 当前不可执行。寻找/移动运行中收到新的寻找或移动返回 01，不替换、不排队；加减速及查询可在忙碌时使用。故障时启动和调档返回 02，停止和查询返回 00，但状态仍是 06。

例如：上电查询回复 `AA 55 02 00 02 0D AA 55 03 00 03 0D`；寻找后回复 `AA 55 02 00 02 0D AA 55 03 01 04 0D`；停止后回复 `AA 55 02 00 02 0D AA 55 03 04 07 0D`。

检查坏校验、坏帧尾、错误 TYPE/CODE 均无回复，随后发送合法帧能恢复。首个候选 AA 起 **满 20 ms** 丢弃残帧；重叠头沿用原截止时间；UART 帧错误立即清除候选。发送二进制字节，不发送字符串 `"AA 55 ..."`。

## 第二步：按键、电脑串口与状态播报

KEY1、KEY2 默认消抖 20 ms，按下后松开，避免按键抖动重复触发：

- KEY1：01 寻找 → 02 接近 → 03 到达；10 移动 → 11 完成；其他状态不改变。**按键只是测试注入，不是传感器到位确认。**
- KEY2：进入 06 故障并主动上报。只有 KEY0 复位可解除；停止、查询和电脑输入都不能解除。
- KEY0：清除队列、计数器、故障及任务状态，回到空闲中档；不会恢复上次任务。

电脑通过板载 USB 串口以文本模式发送 `STATE XX` 加换行（LF 或 CRLF）。例如 `STATE 02`。状态码是两位十六进制，允许大写或小写十六进制数字，关键字必须大写；不接受额外空格或其他格式。最大 8 个正文字符，100 ms 行超时。

| XX | 状态 | ASRPRO 预期播报 |
| --- | --- | --- |
| 00 | 空闲 | 当前空闲 |
| 01 | 寻找 | 正在寻找红色水瓶 |
| 02 | 接近 | 正在接近目标 |
| 03 | 到达 | 已到达目标 |
| 04 | 停止 | 任务已停止 |
| 05 | 失败 | 任务失败 |
| 06 | 故障 | 系统故障 |
| 10 | 移动 | 正在执行移动动作 |
| 11 | 移动完成 | 移动动作已完成 |

按表顺序测试时，06 故障放到最后，或故障后先复位再测试 10/11。输入相同状态不重复上报；查询仍会返回响应和当前状态。ASRPRO 的相同状态语音去重由模块固件负责，FPGA 不重复实现播报去重。注入与按键/命令重合时优先级为物理故障 > 合法语音命令 > STATE 注入 > KEY1；被高优先级事件覆盖的 STATE 请求计入 DBG，不排队。

电脑会收到类似文字（所有数字为十六进制）：

```text
TEST CMD=01 ACK=00 STATE=01 GEAR=1 RX=00000001 BAD=00000000 TMO=00000000 OVF=00000000 DBG=00000000 LOG=00000000
```

CMD 是最近命令，ACK 是此次响应，主动状态或每秒快照的 ACK=FF。GEAR=0/1/2 表示后续动作的低/中/高档，对应未来底盘的 0.05/0.10/0.15 m/s，本工程没有速度输出。RX 为合法命令计数，BAD 为格式/校验/停止位错误计数，TMO 为残帧超时，OVF 为反馈事件丢弃数，DBG 为电脑命令错误/拒绝数，LOG 为调试快照丢弃数。BAD 对一次 UART 帧错误只计一次。

LED3 每次合法命令保持约 100 ms；LED2 表示故障或任何非零错误/溢出计数，清除需复位。日志有独立 32 项快照 FIFO，ASR 反馈有独立 16 项事件 FIFO；每项反馈原子包含完整响应+状态或单个主动状态。满时丢弃新事件并计数，不影响命令处理和停止。协议没有重发与事务 ID，极限突发不保证逐条反馈：输入 6 字节却要输出 12 字节，持续满速输入会超出反馈带宽。正常口令请等待响应完成后再发下一条。

## 第三步：连接 ASRPRO

1. 核对模块供电和 3.3 V UART；确认模块固件已经为当前 `asrpro.hd` 生成识别模型与音频资源并烧录。ASRPRO 目录原有验证记录仅保证代码编译/链接及主机逻辑，不能替代此步骤。
2. 移除外部 USB–TTL 的收发线，改接 ASRPRO TX→P6-5、RX←P6-6，共地。板载 USB 调试线可保留。
3. 唤醒后逐条说工程中的所有口令与同义词，观察 CMD、ACK、STATE；运行中再发寻找/移动应返回忙碌。
4. 验证休眠时停止口令、播报期间停止、停止后新命令、加减速饱和及查询不改变状态。语音识别、休眠和播报抢占效果由模块实测确认。
5. 用 KEY1 或 `STATE XX` 验证全部状态播报、相同状态查询不重复播报、状态切换后再次播报。任意“到达/完成”均是本次人工测试注入，不能当作真实任务验收。
6. KEY2 故障后验证拒绝启动且不能靠停止解除；KEY0 后回到空闲。填写 `records/BOARD_CHECKLIST.md`，不要把仿真通过填作硬件通过。

## 重建与回归

在本目录运行：

```powershell
./run_sim.ps1
& 'D:/Gowin/Gowin_V1.9.12_x64/IDE/bin/gw_sh.exe' build.tcl
& 'D:/Gowin/Gowin_V1.9.12_x64/IDE/bin/gw_sh.exe' verify_saved_project.tcl
python check_reports.py
```

`build.tcl` 明确设置器件、50 MHz、顶层及输出名；`verify_saved_project.tcl` 只打开保存的 `.gprj` 并运行，验证 `impl/*process_config.json` 的 GUI 配置。若 IDE 已打开本工程，修改配置后须关闭重开。两份配置随源码保存，不能当临时构建文件删除。

ModelSim 三套测试均自动检查 completed 与退出码；`records/2026-10-23_P6_VALIDATION.md` 记录实际结果。最终管脚脚本检查 38 个端口、P6 测距映射与其他 CST 的用途冲突（允许明确的同用途独立工程复用）、保存配置、50 MHz 时序、仿真结果及位流 SHA256。异步 UART/按键输入不承诺同步外部 I/O 时序。
