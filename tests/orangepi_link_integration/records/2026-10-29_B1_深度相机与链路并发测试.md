## 1. 连接拓扑（实测枚举结果）

```
FPGA GW5A-25A ──(板载 USB 串口 CH9102, VID:PID 1a86:55d4)──> Orange Pi USB
       │                                                     └─ /dev/ttyACM0
       │                                                        (by-id: usb-1a86_USB_Single_Serial_5757024820-if00)
       └── JTAG 下载线 ──> PC（烧位流用，与串口互不影响）

                      ├─ 2bc5:050f  USB 2.0 Camera（RGB）
                      └─ 2bc5:060f  ORBBEC Depth Sensor（深度）
```

> 注意：CH9102 在 Linux 下枚举为 **CDC-ACM `/dev/ttyACM0`**，不是 `/dev/ttyUSB0`。
> 测试工程已改为「按 by-id 自动识别」，避免每次换口改配置。

## 4. 本轮修掉的缺陷（都在测试工程里）

1. **`Link.telemetry` 只有 2000 深**：长跑（>40 s @50 Hz）时按下标取帧会停在上限，
   120 s soak 只记录了 2000/6001 帧。已改成**边收边 drain**，现在记录数与解析数一致。
2. **冷启动半帧噪声**：打开串口瞬间从半帧开始，会产生 10~22 个 `sync_err`，被误判成
   "链路有错"。已改为**预热 0.5 s 后再统计**（预检、采集、soak 全部生效）。
3. **端口识别**：原来写死 `/dev/ttyUSB0`，实际设备是 `/dev/ttyACM0`。已改为
   by-id 自动识别（`*1a86*` / `*CH9102*` / `*CH340*`），PC/Pi 通用。
4. 相机判定语义：要求开相机却打不开时，`camera_opened` 直接 FAIL（此前会"假通过"）。

## 5. 结论与下一步

- ✅ **相机与链路可共存**：8 fps 深度流下，50 Hz 遥测仅掉到 49.0 Hz（单帧抖动），
  CPU 约 31%，说明 Pi 的算力与 USB 带宽都有充足余量。
- ✅ **遥测质量足以建图**：帧间隔抖动 ≤0.1 ms、心跳年龄 ≤94 ms、yaw 静态漂移 0.01°/s。
- 下一步（需在测试目录继续）：
  1. 把每帧遥测与相机帧**时间戳对齐**（同一个单调时钟），供 `occupancy.py` 融合；
  2. 相机 15 fps / 30 fps 下复测，找 CPU 拐点；
  3. 编码器速度标定后，用链路返回的里程计替代视觉里程计做交叉验证。
