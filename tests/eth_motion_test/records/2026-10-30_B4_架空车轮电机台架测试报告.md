## 3. 过程中发现并修掉的问题（工具侧，非固件）

1. **步骤收尾的 STOP 被误判为异常**：台架脚本统计故障窗口时把"步骤结束时主动 STOP"的 0x01 也算进去了 → 已改为只统计停车前窗口。
2. **旧 ACK 干扰判定**：`wait_ack` 会匹配队列里的历史 ACK，导致"停止后 SET_VEL"看起来是 OK → 已改为先清空 ACK 队列并用 seq 精确匹配。
3. 长稳脚本的 CPU 采样和起步建链窗口误判 → 已修。

> 这三处都是测试脚本的问题，固件行为自始至终符合设计。

## 4. 安全行为（本轮实测确认）

| 场景 | 实测表现 |
| --- | --- |
| 行驶中 STOP | 立即停 + 锁存，后续 SET_VEL 返回 `REJECT_STOP_LATCHED`，必须 CLEAR 才能恢复 ✅ |
| 行驶中心跳丢失（模拟断网） | 300 ms 心跳超时后 LINK_LOST 锁存，SET_VEL 返回 `REJECT_LINK_LOST` ✅ |
| 恢复 | 恢复心跳 + CLEAR 后可正常驱动 ✅ |
| 快速换向 | 无异常 ACK、无故障位置位，换向经过驱动内部死区 ✅ |

## 6. 已知限制

1. 本测试位流**不读编码器**，遥测里 `enc_l/enc_r` 恒为 0 → 无法定量测转速/里程；方向与转速只能目视。
2. 速度是开环映射（`duty = v×20`，300 mm/s≈96% 占空比），没有 PID 闭环。
3. 急停键（KEY2）需要**人工按住**才能测，本轮未做（等效安全路径已由 STOP/心跳丢失覆盖，且仿真里已单独验证）。
4. `CMD_TIMEOUT=500 ms`：命令必须 ≥10 Hz（本轮 20 Hz）。
