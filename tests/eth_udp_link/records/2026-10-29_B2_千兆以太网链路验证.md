## 1. 拓扑

```
FPGA 板 RJ45 ──────────────── Orange Pi eth0（直连，1000 Mb/s full duplex）
   FPGA: MAC 00:0a:35:01:fe:c0 / IP 192.168.0.2 / UDP 5000（例程固定）
   Pi  : IP 192.168.0.1/24（NM 连接 ethfpga，never-default）
         静态 ARP: 192.168.0.2 -> 00:0a:35:01:fe:c0（例程不实现 ARP）
```

## 2. 关键问题与修复（本次核心结论）

**现象**：烧厂商预编译位流后，Pi 侧 `tx_packets` 正常增长而 **`rx_packets` 一直为 0**，
FPGA 一个包都不发。

**根因**：厂商 `eth_udp_lookback_rgmii.fs` 是 2023-08-18 用 **V1.9.9 Beta-2 + GW5A-LV25UG324ES
（ES 硅片）** 编的；文件头里 PLL 参数为 `FCLKIN=125, IDIV_SEL=1, FBDIV_SEL=1, ODIV0_SEL=7`。
在 GW5A-25A **C2/I1** 上这些参数非法/锁不住（PFD=125 MHz 超出 19~87.5 MHz 范围）——
整个设计唯一时钟来自 PHY 的 `rgmii_rx_clk` 经该 PLL，**PLL 不锁 → 全设计无时钟 → 零流量**。

**修复**：用 Gowin EDA V1.9.12 以 `GW5A-25A / GW5A-LV25UG324C2/I1` 重新综合，PLL 参数按公式重算：

| 参数 | 原值(ES) | 新值 | 说明 |
| --- | --- | --- | --- |
| `IDIV_SEL` | 1 | **2** | PFD = 125/2 = **62.5 MHz**（合法区间 19~87.5） |
| `FBDIV_SEL` | 1 | **2** | VCO = 125×2×7/2 = **875 MHz**（合法 700~1400） |
| `MDIV_SEL` | 7 | 7（保持） | |
| `ODIV0_SEL` | 7 | **7** | CLKOUT0 = 875/7 = **125 MHz** |
| `PE_COARSE/FINE` | 5/2 | 5/2（保持） | RGMII RX 采样相位；本次一次通过，未需扫描 |

重编后立刻通：100/100 回包。厂商原 .fs 与重编 .fs 都留在仓库里便于对照
（`impl/pnr/vendor_eth_udp_loopback_rgmii.fs` vs `impl/pnr/eth_udp_link.fs`）。

## 3. 分级测试结果

| 用例 | 发送 | 回包 | 丢包 | pps | RTT min/中位/p95/max (ms) |
| --- | --- | --- | --- | --- | --- |
| 200 × 32 B @10 ms | 200 | 200 | **0%** | 99 | 0.059 / 0.063 / 0.080 / 0.135 |
| 500 × 32 B @5 ms | 500 | 500 | **0%** | 196 | 0.058 / 0.062 / 0.081 / 0.117 |
| 1000 × 64 B @2 ms | 1000 | 1000 | **0%** | 475 | 0.058 / 0.077 / 0.079 / 0.123 |
| 2000 × 128 B @1 ms | 2000 | 2000 | **0%** | 904 | 0.048 / 0.066 / 0.078 / 0.122 |
| **3000 × 128 B 突发** | 3000 | 3000 | **0%** | **3692** | — / 0.066 / 0.070 / 0.119 |
| 500 × **1400 B** @1 ms | 500 | 500 | **0%** | 719 | — |

> 3692 pps × 128 B ≈ **3.8 Mbps**；719 pps × 1400 B ≈ **8 Mbps**。
> 上限由 Pi 侧 Python 单线程收发决定，不是 FPGA/PHY 的极限（125 MHz RGMII 理论 1 Gbps）。
> 对链路需求（50 Hz × 30 B = 12 kbps）来说余量 > 300 倍。

## 4. Pi 侧准备（已应用）

```bash
sudo nmcli connection add type ethernet ifname eth0 con-name ethfpga \
    ipv4.method manual ipv4.addresses 192.168.0.1/24 ipv4.never-default yes ipv6.method disabled
sudo nmcli connection up ethfpga
sudo ip neigh replace 192.168.0.2 lladdr 00:0a:35:01:fe:c0 dev eth0 nud permanent
python3 tools/udp_echo_test.py --count 200 --interval 0.01
```

## 5. 结论与下一步

- ✅ **1GbE PHY + RGMII + UDP 收发在 GW5A-25A（C2/I1）上可用**，延迟 ~0.07 ms、零丢包。
- ✅ 例程无 ARP → 必须静态 ARP（已写入配置）；后续自研 RTL 建议实现 ARP 响应，省掉这一步。
- 下一步（把链路协议搬上以太网，PROTOCOL §7）：在 FPGA 侧加一个「UDP payload → 字节流」
  适配器接到 `host_frame_rx`（注意 §5.2 的字节间隙要求），遥测侧把 `frame_tx_engine`
  输出写进 UDP payload；上位机直接用 `tests/uart_bridge/tools/transport.py` 的 `UdpTransport`。
