## 8. 轮轴位置与转向空间（2026-10-31 11:30 实测参数，重要）

实测：**驱动轮中心离车尾约 25 mm**（轮轴几乎在最尾端）。

因此（以轮轴为旋转中心）：
- 车头向前 **295 mm**（320−25）、车尾向后 25 mm、半宽 120 mm；
- **原地转向扫掠半径 = √(295²+120²) ≈ 319 mm** —— 几乎就是整车长度在转；
- 600 mm 走廊中心离墙 300 mm **< 319 mm → 走廊里原地转不开**；
- 只有开阔处（净空 ≥ ~0.8 m，或路口/区域外）才能原地转向。

对明天测试的影响：

1. **转向类测试（seg3/4/5）必须在场地开阔处做**（如场外空地、或 ≥0.8 m 净空的角落），
   不要在 600 走廊里试原地转，会蹭墙。
2. **路线测试用 `--manual-turn` 模式**：程序遇到转向段会提示
   "请把车原地转到 ±X°（相对当前车头），回车继续"，由人完成转向——
   里程/直行仍由程序精确执行，这样既不会蹭墙，又能把整条路线走完：
   ```bash
   python3 ~/t4_tools/run_segments.py --suite routes --speed 25 --manual-turn
   ```
3. 连续 ABCDE 同样用 `--manual-turn`（3 处倒车段程序会自动倒，转向由人完成）。
4. 我已经把地图假设更新为：`axle_from_rear_mm=25 / body_front_mm=295 / turn_sweep_radius_mm=318.5`，
   规划器/仿真使用同一几何。

后续可做（需要的话）：三点掉头（前进-倒车转向-前进）自动实现，这样在 600 走廊/路口里
可以不用人工转向；以及把"倒车到路口"做成自动序列。明天先在现场确认哪些路口净空 ≥0.8 m。

## 9. 三点掉头（自动段，2026-10-31 新增）

人工转向的替代方案，执行序列（绕轮轴）：
1. **前进弧**（vl=v+Δ, vr=v−Δ）转一部分角；
2. **倒车弧**（vl=−v+Δ, vr=−v−Δ）继续同向转；
3. **前进弧** 收尾到目标角。

参数在 `calib.json` 可调：`tp_v`（弧线速度，默认 40）、`tp_diff`（左右差速，默认 40）、
`tp_fracs`（三段比例，默认 [0.45,0.35,0.20]）；先空旷处标定再进走廊。

### 测试顺序（新增）

```bash
# 单段三点掉头（空旷处，前方/侧方各留 >=1 m）
python3 ~/t4_tools/run_segments.py --only seg9_threepoint_90
python3 ~/t4_tools/run_segments.py --only seg10_threepoint_180

# 路线：所有"原地转"改为三点掉头（倒车段仍自动）
python3 ~/t4_tools/run_segments.py --suite routes --speed 25 --three-point
python3 ~/t4_tools/run_segments.py --only route5_ABCDE_plan --speed 25 --three-point
```

### 调参方法（现场 2 分钟）

1. 空旷处跑 `seg9_threepoint_90`，看终点 yaw 误差与车体是否越界；
2. **转不够**：`tp_diff` 调大（35→50）或 `tp_fracs` 首段加大；
3. **转太多/蹭墙**：`tp_v` 调小（40→30）、`tp_diff` 调小；
4. 满意后把三个值写进 `~/t4_tools/calib.json`（键名 `tp_v/tp_diff/tp_fracs`），后续路线自动使用。

> 若 600 走廊里三点掉头也放不下，就退回 `--manual-turn`（人工转向），这是最保底的方式。

## 10. 弧线转向（边走边转，600 走廊可过）—— 最终推荐的转向方式

数值验证结果：在 600 mm 的 L 型路口，车以 **半径 200 mm 的弧线**边走边转 90°，
整车轮廓最小余量 **64.8 mm**（可行）；而原地转向扫掠半径 319 mm > 300 mm（不可行）。

执行原语：
- `arc_turn(deg)`：左右轮差速 `vl=v(1-track/2R)`, `vr=v(1+track/2R)`，绕 R 圆弧转到目标航向；
- 参数从 `calib.json` 读：`arc_radius`（默认 200）、`arc_v`（默认 60）、`wheel_track`（默认 240）。

测试与使用：

```bash
# 空旷处标定弧线转向（前方/侧向留 >=1 m）
python3 ~/t4_tools/run_segments.py --only seg11_arc_90        # 右转90 + 左转90 回原向
python3 ~/t4_tools/run_segments.py --only seg12_arc_L         # 直行300 + 弧线右转 + 直行300

# 路线：已按弧线转向重新规划（A->B / A->C / A->E）
python3 ~/t4_tools/run_segments.py --only route1_A_to_B_plan --speed 40 --arc
python3 ~/t4_tools/run_segments.py --only route2_A_to_C_plan --speed 40 --arc
python3 ~/t4_tools/run_segments.py --only route4_A_to_E_plan --speed 40 --arc
```

说明：
- 路线 JSON 里转向段的类型是 `{"type":"arc","deg":±45}`（每段 45°，两段=90°），执行器自动识别；
- A→D 和连续 ABCDE 目前用弧线规划不出完整路径（需要"倒车到更宽路口"的组合动作），
  保持旧文件/人工转向；等明天现场确认哪些路口净空最大后，我再补"倒车 + 弧线"的组合规划。
- 弧线半径与速度要现场标定：若压线就把 `arc_radius` 调大（200→260）或 `arc_v` 调小。
