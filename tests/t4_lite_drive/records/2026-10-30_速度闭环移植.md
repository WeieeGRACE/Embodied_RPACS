## 2. 控制律

```
control[n+1] = clamp( control[n] + (KP*de + KI*e + KD*dd) >> GAIN_SHIFT, ±DUTY_LIMIT )
e  = target_counts_per_window - filtered_counts_per_window   (counts/窗口, 整数)
de = e[n] - e[n-1];  dd = e[n] - 2e[n-1] + e[n-2]
饱和且误差继续向外时去掉 I 项（条件积分，与主工程一致）
```

数据流（全部 clk125m 单时钟域）：

```
delta_count(±1/clk) -> speed_measurement_and_velocity_filter（20 ms 窗口 + 4 点平均）
  -> target: mm/s -> counts/窗口（146/1024 定点，四舍五入）
  -> dual_speed_pi_pid_controller（增量式 PI）
  -> pwm_and_startup_ramp（duty 每 PWM 周期最多 1 tick）
  -> tb6612_driver_interface（原样） -> TB6612
```

## 3. 参数与标定依据

| 参数 | 值 | 依据 |
| --- | --- | --- |
| `SPEED_WINDOW_MS` | **20 ms**（主工程 10 ms） | 50 mm/s 在 20 ms 窗口 = 7.13 counts，取整 7 = **49.1 mm/s（-1.8%）**；若沿用 10 ms 只有 3.56 counts，取整 4 = 56.1 mm/s（+12%） |
| `SPEED_KP` | **16** | 与主工程 `KP=32 @10 ms` 连续域等效：16 tick / 7.01 mm/s = 32 tick / 14.03 mm/s ≈ 2.28 tick/(mm/s) |
| `SPEED_KI` | **4** | 主工程 `KI=1 @10 ms` 约 4 倍积分速率；SET_VEL 阶跃 90% 建立时间 ~2 s -> ~0.6 s（Python 模型扫描，稳定、峰值过冲 <1%） |
| `SPEED_KD` | 0 | 与主工程一致 |
| `SPEED_GAIN_SHIFT` | 0 | 与主工程一致 |
| `SPEED_DUTY_DIV` | 2（duty ≤ 50% = 3125 拍） | 主工程为 25%；按旧开环实测（duty≈1000 tick -> 110 mm/s，约 9.1 tick/(mm/s)），50% 对应 ~340 mm/s，覆盖 `MAX_V_MM_S=300`（300 mm/s 实测用 ~2544 拍 = 41%）；同时给“编码器失效积分灌满”留 50% 余量 |
| `SPEED_RAMP_STEP` | 1 tick/PWM 周期 | 主工程同值；0→455 拍约 22.8 ms，启动/换向无冲击 |
| 目标换算比例 | 146/1024 = 0.142578 counts/(mm/s)/窗口 | 精确值 20 µm×1456/204203 µm = 0.14260，误差 -0.02%（与 task4 的 73/1024 同思路，避免宽位乘法关键路径） |
| 速度窗口量化 | 1 count = 7.01 mm/s | 20 ms × 1456 counts / 204203 µm 轮周长 |

## 4. 仿真证据

`sim/tb_wheel_speed_loop.sv`：真实 125 MHz / 20 kHz PWM / 20 ms 窗口（**不做时间
缩放**，duty 分辨率 1/6250、counts/窗口量化与上板一致）；被控对象为一阶电机 +
编码器模型，参数由旧开环实测标定：duty≈1000 tick 稳态 ~110 mm/s → 增益
0.1222 mm/s/tick（含 100 tick 静摩擦死区），时间常数 50 ms。

| 场景 | 结果 |
| --- | --- |
| V1 使能前 | STBY=0、duty=0 |
| V2 SET_VEL(50,50) | **49.91 / 49.91 mm/s**（filtered 7 counts/窗口，duty≈508 拍，误差 0.2%），方向正确 |
| V3 SET_VEL(100,100) | 97.06 / 97.06 mm/s（取整 14 counts = 98.2，-1.1%） |
| V4 原地转 (+50,-50) | **+54.3 / -48.9 mm/s，差速 103.1 mm/s**；@240 mm 轮距 yaw **-24.6 °/s** |
| V5 SET_VEL(-50,-50) | -49.86 / -50.35 mm/s，方向翻转正确 |
| V6 SET_VEL(0,0) | duty 归零，轮速衰减到 ~-2 mm/s |
| V7 enable=0（安全门关断） | duty 立即 0、STBY=0 |
| V8 SET_VEL(300,300) | 296.2 / 296.0 mm/s，duty=2544 拍（未顶到 3125 限幅） |
| 合计 | **24 项检查全 PASS**（`records/tb_wheel_speed_loop.log`） |

`run_motion_sim.ps1` 全量回归（`records/run_motion_sim_final2.log`）：

```
bridge    PASS   records/tb_bridge.log
unit      PASS   records/tb_unit.log
system    PASS   records/tb_system.log
speedloop PASS   records/tb_wheel_speed_loop.log
All motion simulation suites passed.
```

**仿真抓到并修掉的问题**：mm/s→counts 换算第一版用 `~target_q + 17'd1` 取绝对值，
因为 `17'd1` 是无符号数，`~` 的操作数被零扩展，负目标 (-50) 被算成 65586 counts
（→ PI 直接反向饱和到 50% duty，-370 mm/s）。改为显式符号扩展
`{{1{target_q[15]}}, target_q}` 后，负目标/反向验证全部 PASS。

## 6. 风险 / 限制（上板前注意）

1. **反馈量化**：20 ms 窗口 1 count = 7.0 mm/s。稳态条件是 `filtered == target counts`，
   实际轮速可落在目标上方最多 ~0.75 count（50 mm/s 目标最多 ~54.4，从低速侧逼近则
   ~49.9）。这是 counts/窗口方案的量化极限；要更准可改 40 ms 窗口或改用
   `asr_distance` 的 µm 差分测速（0.05 mm/s 级分辨率），但需要重新验证。
2. **编码器失效**：PI 只依赖编码器；若编码器线断/无增量，PI 会在大约 1 s 内把 duty
   积分到 50% 上限。本工程按任务要求未改安全门（`encoder_fault` 仍未接入 fault），
   上板前务必确认编码器线束；若要更强保护可把 `enc_fault_l/r` 并入 `fault_bits`
   （会改变既有安全逻辑，需 Lead 确认）。
3. **PI 参数是在一阶对象模型上整定的**，实车电机增益/摩擦不同；`SPEED_KI` 从 4
   往小调更保守，上板后用遥测 `speed_l/r` 复核。
4. 125 MHz 域仍按 PnR 默认 100 MHz 基准分析（沿用此前所有位流口径）；本次最差
   SETUP slack +0.691 ns。若要把 8 ns 真实约束写进 SDC 需重新收敛（本次未做）。
5. 旧 `eth_motion_bridge` 的开环 `to_duty` 仍留在文件里供旧仿真套件使用，但顶层已不
   连接它的 `pwm_l/pwm_r`，综合时被裁掉，不进入位流。
6. 未烧板、未提交；**板上实测前不要直接按 ~110 mm/s 的旧经验设置 STOP 提前量**
   （闭环后实际速度≈命令值，停车距离与旧开环行为不同）。
