# ASRPRO 简单运动控制上板测试

这是独立测试工程，适用于 ACG525 / GW5A-LV25UG324C2/I1。支持前进、后退 20 cm，以及原地左旋、右旋 90°。上电静止完成 IMU 校准后才接收移动命令；无电脑心跳要求，上电不运动。距离参数仍为名义初值。

2026-10-23 实机手转数据显示右转约 +89°、左转约 -90°，故两版共用的 `YAW_SIGN` 已改为 -1，目标角度保持 90000 毫度。修正版仿真及两版编译通过后，用户已确认 **ASRPRO 独立语音控制上板测试通过**。详见 [上板测试报告](records/2026-10-23_ASRPRO独立语音控制上板测试报告.md)。精确停转角度、越程、距离误差和五次重复性仍待测量记录。

## 选择下载文件

| 用途 | Gowin 工程 | SRAM 下载文件 | 串口 RX / TX |
|---|---|---|---|
| 电脑发送协议、标定及初次测试 | `asr_motion.gprj` | `impl/pnr/asr_motion_test.fs` | U8 / V8，板载 USB 串口 |
| ASRPRO 独立语音控制 | `asr_motion_gpio.gprj` | `impl/pnr/asr_motion_gpio.fs` | D17 / D18，独立 GPIO |

两版 RTL、运动参数和协议相同，仅串口管脚及输出文件名不同。U8/V8 是板载 USB 串口，不能同时将 ASRPRO TX 接到 U8，让两个 TX 输出共同驱动。语音版改用规划中的 D17/D18；这里列的是 **FPGA 球位**，不是连接器的第 17/18 针。按开发板原理图或引脚表确认对应引出位置再接线。

在 Gowin Programmer 中选择匹配的 `.fs`，下载到 SRAM。无需更改、下载主工程。KEY0/B16 复位，KEY2/C15 急停；KEY1/A15 仅用于进入被动标定模式，不触发运动。

## 接线与显示

保留已验证的电机和 IMU 接线，不增加硬件：

| 信号 | FPGA 球位 |
|---|---|
| 左编码器 A / B | C17 / C18 |
| 右编码器 A / B | F14 / G14 |
| PWMA / AIN1 / AIN2 | U17 / M16 / M14 |
| PWMB / BIN1 / BIN2 | T17 / N15 / H12 |
| STBY | G13 |
| IMU SCK / MOSI / MISO / CS | V15 / V16 / U18 / T18 |
| IMU INT1 / INT2 | N14 / N16，轮询模式不依赖中断 |
| IMU 地线预留 | T11，始终为无上下拉输入 |

语音版：ASRPRO 的实际 UART TX 引脚 → D17（GPIO4／P6-5）；UART RX ← D18（GPIO5／P6-6）；GND 共地，使用 P6-12 或 P6-30 专用地。注意不是 P11 的 LCD_GPIO4/5。模块内配置为 Serial1、PA2/TX、PA3/RX，需按所购模块的实际引出确认。FPGA UART 为 3.3 V LVCMOS，不能输入 5 V UART；模块供电按其型号说明连接。本测试不改变 ASRPRO 固件，需要模块已有的语音词表／协议固件。

LED：D14=就绪，C14=正在动作（含等待停稳），B9=故障，A9=被动标定模式。普通控制模式下 A9 不表示心跳。本测试不驱动 OLED，未集成测距避障；请在清空障碍的测试区域操作。

复位后保持车体静止约 1～2 秒，等待 D14 亮。IMU 按 200 Hz 采样，前 200 个样本估计零偏。当前安装已采用 `YAW_SIGN=-1` 修正；若之后改变安装方向，需重新被动检查左旋航向增加、右旋减少，不能靠交换转向口令掩盖反馈符号错误。

## 先用电脑验证

在本目录运行 PowerShell，无需额外串口库。将 `COM6` 替换为实际板载串口号，关闭其他占用该端口的软件：

```powershell
./serial_test.ps1 -Port COM6 -Action status
./serial_test.ps1 -Port COM6 -Action forward
./serial_test.ps1 -Port COM6 -Action backward
./serial_test.ps1 -Port COM6 -Action left
./serial_test.ps1 -Port COM6 -Action right
./serial_test.ps1 -Port COM6 -Action stop
```

工具每次只发送一条二进制命令，不自动重试。移动命令默认最多等待 15 秒，以收到 `DONE` 为成功；忙／不可执行／故障返回退出码 2，未确认完成返回 1。关闭工具或电脑断开不会取消动作，板上每次动作有独立 10 秒总超时；需要立即停止时按 KEY2。`monitor` 仅接收，`faster` / `slower` 更新后续动作档位，`search` 用于确认寻找任务被拒绝。

原始协议为 115200/8N1，`AA 55 01 CODE CHECK 0D`，`CHECK=(1+CODE)&255`。发送原始字节，不是十六进制文本。

| 动作 | CODE | 完整帧 |
|---|---|---|
| 停车 | 02 | `AA 55 01 02 03 0D` |
| 查询 | 03 | `AA 55 01 03 04 0D` |
| 前进 20 cm | 10 | `AA 55 01 10 11 0D` |
| 后退 20 cm | 11 | `AA 55 01 11 12 0D` |
| 原地左旋 90° | 12 | `AA 55 01 12 13 0D` |
| 原地右旋 90° | 13 | `AA 55 01 13 14 0D` |
| 加速 / 减速 | 14 / 15 | `AA 55 01 14 15 0D` / `AA 55 01 15 16 0D` |

每条合法命令返回 TYPE=02 响应，再返回 TYPE=03 当前状态。响应 00=接受，01=忙，02=不可执行；状态 00=空闲、04=已停车、06=故障、10=移动中、11=完成。状态变化主动上报；完成只在达到目标且双轮连续三个 10 ms 测速窗口无计数后上报。停车过程中仍显示移动中，停稳后回报 04，不回报完成。寻找命令 `01` 返回不可执行。

运行中移动命令不替换动作、不排队，需先停车。速度档位为 0.05、0.10、0.15 m/s，默认中档；加减速在端点饱和，仅影响后续动作。旋转轮速固定限制为 0.05 m/s。转换到整数 counts/10ms 后有速度量化，默认约为 4、7、11；不保证实际速度恰好等于名义档位。

协议没有事务号，请等待反馈后再发下一条，避免持续灌入命令。发送缓冲最多保存 64 个反馈帧；长期输入快于反馈发送导致溢出会锁存停车，待缓冲排空后补发故障状态。溢出的命令反馈可能丢弃；停车解析与硬件关断不依赖发送缓冲。

## 距离及方向标定

首次先架空车轮，用低速单动作确认正反方向及急停。以下参数集中在 `src/asr_motion_test_top.v` 顶层，修改后重新生成两版位流：

| 参数 | 初值 | 含义 |
|---|---|---|
| `COUNTS_L` / `COUNTS_R` | 1456 | 每侧车轮一圈四倍频后计数，来自 13 PPR × 28 × 4，未实测 |
| `UM_PER_REV_L` / `UM_PER_REV_R` | 207345 | 每侧有效轮周长，单位 µm，约等于 π × 66 mm，未实测 |
| `YAW_SIGN` | -1 | 按实机手转数据反相，统一为左旋正、右旋负；两版共用 |
| `GOAL_UM` / `GOAL_MDEG` | 200000 / 90000 | 20 cm / 90° |
| `KP` / `KI` / `KD` | 32 / 1 / 0 | 已有双轮 PI 初值 |
| `ACTION_MS` | 10000 | 包括加速、运行、减速、停稳的总超时 |

被动标定使用同一位流：**按住 KEY1，再按下并释放 KEY0，保持 KEY1 至 A9 亮后松开**。此模式完全禁止电机输出，可安全手转车轮；没有协议响应，仅每 200 ms 输出一行原子快照：

```text
L=000005B0 R=00000000 Y=00015F90
```

L/R 是有符号 32 位累计编码器 counts，Y 是解缠绕后的毫度，均为补码十六进制。电脑版可直接读取并转为十进制：

```powershell
./serial_test.ps1 -Port COM6 -Action calibration -Seconds 60
```

语音 GPIO 版的诊断仍走 D17/D18，需要 3.3 V USB-TTL 适配器；通常先用电脑版标定，再下载语音版。

1. 在轮上做标记，各自向前手转完整一圈，记录 L/R 的增量。两侧向前均应为正，把绝对值分别填入 `COUNTS_L/R`。默认相序沿用已验证的左反相、右正相解码。
2. 退出标定模式需松开 KEY1 后按 KEY0。回到普通模式，架空确认前进、后退和左右旋转方向；准备好 KEY2 急停。
3. 在地面标出起点，让车沿直线低速执行动作，测量实际位移。可在停止后进入标定模式手推已知距离 200 mm，记录两侧计数增量 N；分别计算 `UM_PER_REV = 200000 × COUNTS_PER_REV / abs(N)`。轮胎保持接地、不打滑，测多次取平均。
4. 修改参数重编译后，再实测 20 cm。若只用动作实际位移 D 修正，近似公式是 `新 UM_PER_REV = 旧 UM_PER_REV × D / 200 mm`；动作减速越程会影响此方法，优先采用手推标定。
5. 标定模式下手动将车体左旋约 90°，确认 Y 增加约 90000；右旋应减少。相对航向无绝对方向基准，会随时间漂移。每轮正式测试前保持静止复位校准。

距离用各轮独立标定值换算，Q16 小数相位持续保留；动作中不清编码器计数。每轮分别达到距离后减速，因此允许到位先后不同。现有动作状态机在达到目标后减速，没有制动距离预测，存在实机越程；本版本不增加 IMU 直行纠偏或定位融合。

## 停车与异常

- KEY2 是硬件急停，亚时钟短脉冲也锁存；KEY0 清除并重新校准。释放 KEY2、恢复串口或传感器不会自动重启。
- IMU 初始化／健康检查错误、ready 丢失或 100 ms 无有效样本／姿态更新时禁止继续运动。
- 编码器非法跳变、左右测速超过 100 ms 未更新、动作超时、等待停稳超过 1 秒均锁存故障，切断 PWM、方向和 STBY。
- 编码器断线可能表现为持续零计数，仍有“新测速窗口”；此时依靠动作总超时停车。没有宣称可区分编码器断线、堵转和车轮被夹住。
- 最大 PWM 为 20 kHz 周期的 25%，PI 与启动斜坡复用现有实现；零速窗口期间释放驱动等待停稳。电源、电机驱动和轮胎惯性仍需实机验证。

## 重现仿真和编译

从本目录运行，脚本会自行定位工程目录：

```powershell
./run_sim.ps1
& 'D:/Gowin/Gowin_V1.9.12_x64/IDE/bin/gw_sh.exe' build.tcl
& 'D:/Gowin/Gowin_V1.9.12_x64/IDE/bin/gw_sh.exe' build_gpio.tcl
python check_reports.py
python check_reports.py --gpio
```

`verify_saved_project.tcl` / `verify_gpio_project.tcl` 从保存的 `.gprj` 启动完整编译，不重新设置顶层／频率／IO 选项，用于确认 IDE 工程配置可重开。CPU 和 SSPI 均须作为普通 IO，频率 50 MHz。两个工程各有对应 `impl/*process_config.json`，请保留。打开已缓存的工程需关闭重开以加载设置。

完整联合仿真采用 1 MHz 逻辑时钟、1 kHz PWM 和独立双电机物理模型加速，保留 5 ms IMU 采样、10 ms 测速、真实 20 cm / 90° 目标和 10 秒总超时。额外的 50 MHz 冒烟测试使用实际 115200 baud、1 MHz SPI、20 kHz PWM 和 10 ms 测速；仅缩短启动等待及校准样本数。模型不替代实物测量。

共享姿态模块仅新增可选 `update_valid` 输出，每次角度提交时脉冲一次；现有端口及运算保持原行为，已运行原有系统／姿态／OLED／电机回归。测试结果和最终构建校验值见 `records/VALIDATION.md`。
