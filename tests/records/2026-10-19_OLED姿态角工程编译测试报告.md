## 2. 故障与修复

原始布局布线错误为 `PR2028` 和 `PR2017`：OLED 的 R3/T3 被作为 CPU/SSPI 专用引脚处理，无法按普通 IO 放置。早期 Tcl 构建虽然通过，但不能据此判断已打开的 IDE 工程配置正确；实际 IDE 构建曾复现该错误。

在 IDE 中启用 **Use CPU as regular IO** 和 **Use SSPI as regular IO**，保存配置，并设置测试顶层、50 MHz 及输出名。关闭并重新打开工程后，配置界面确认频率为 `50.000 MHz`，再执行完整 Run All。

实测此版本 IDE 保存的配置文件为 `impl/imu_attitude_oled_process_config.json`，`gw_sh` 也读取该文件。`impl/project_process_config.json` 保留为同步副本；仅补该通用文件未能修复此前 IDE 的旧配置。两份文件内容已同步，并加入 Git 跟踪。工程已打开时，外部修改文件可能被 IDE 内存中的旧配置覆盖，应关闭工程后更新，再重新打开。

## 4. 管脚核对

管脚约束与生成的管脚报告一致，以下 10 个端口无重复物理管脚分配。

| 信号 | 管脚 | 用途 |
| --- | --- | --- |
| `clk_50m` | T9 | 系统时钟 |
| `reset_n` | B16 | 复位 |

| `imu_spi_mosi` | V16 | IMU SPI 发送 |
| `imu_spi_miso` | U18 | IMU SPI 接收 |
| `imu_cs_n` | T18 | IMU 片选 |
| `imu_int1` | N14 | 保留，未使用 |
| `imu_int2` | N16 | 保留，未使用 |

OLED 两个端口均为 `LVCMOS33`，报告中的电压为 3.3 V。与本独立工程的 IMU、时钟和复位信号无管脚冲突。
